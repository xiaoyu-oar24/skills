# code-search-discipline 触发评测集

> 评估驱动开发：修改 `description` 或触发条件后，用以下提示词回归验证路由行为。

## 应触发（Expected：激活）

1. "帮我搜一下 getUserInfo 在哪些文件里"（符号定义定位）
2. "这个报错文案 'Network timeout' 出现在源码哪一行"（字面量精确查找）
3. "登录流程是怎么实现的，调用了哪些服务"（大型源码语义理解）
4. "AuthService 被哪些地方调用了，修改它有什么影响"（调用关系与影响面分析）
5. "src 目录下有哪些 .vue 页面组件"（文件类型枚举）
6. "帮我查一下项目里 z-paging 组件都用在哪些页面了"（跨页面特定组件使用排查）
7. "用 grep 找一下 VITE_API_BASE 这个配置常量在哪定义"（配置键查找）
8. "全局搜索一下 payOrder 函数在哪些业务模块被调用"（跨模块广域搜索）

## 不应触发（Expected：跳过）

1. "帮我读一下 src/utils/format.ts 的内容"（已知路径单文件 → 直接 Read）
2. "这个项目的 aidocs 文档太多，帮我瘦身、降低 Token 消耗"（文档治理 → lean-docs）
3. "帮我开发一个新功能"（单凭此意图不触发搜索纪律；实际进入代码搜索时再触发）
4. "把 aidocs 目录按五维象限归类整理"（文档布局维护 → docs-layout-quadrant）
5. "帮我改一下 src/pages/index.vue 的按钮样式"（单文件局部修改，不涉及搜索）

## 工具路由回归（Expected：先检查，适用时 codegraph 优先）

| 场景与前提 | 预期行为 |
| :--- | :--- |
| 首次理解登录流程，工具已暴露、项目有索引 | 先确认项目与工具参数，用一次有界 explore 查询验证并获取上下文，不先 grep |
| MCP 启动目录无索引，目标项目有索引 | 传入目标项目路径查询，不能误判 MCP 整体不可用 |
| 工具未暴露，宿主提供延迟发现能力 | 做一次针对性发现；仍不可用则记录原因并降级，不猜工具名 |
| 项目无索引，同一项目连续查询两个符号 | 首次检查后降级，第二次复用状态；不重复探测、不自动初始化 |
| 查询报连接错误或索引损坏 | 记录具体原因并降级；不重复失败调用，不自行安装或重建 |
| 精确搜索 Network timeout，codegraph 未声明文本检索能力 | 检查能力后直接受限 rg -F，不额外做语义查询探活 |
| 用户明确要求“用 grep 找 VITE_API_BASE” | 技能触发以约束搜索范围，但尊重工具选择，不强加 codegraph 探测 |
| codegraph 返回相关完整源码与调用链 | 直接分析；不重复 Read 或 grep，摘要或截断源码才需定点补读 |
| codegraph 0 命中，或文件刚改动而索引未同步 | 不断言源码不存在或索引已更新；通过受限搜索或 Read 核实 |
| 切换项目，或用户明确告知索引已建立 | 对新的项目状态重新检查，不沿用旧项目的不可用结论 |
| 需要枚举未索引的新建 Vue 文件 | 使用限定目录或类型的 glob / rg --files，不能把索引清单当作完整文件列表 |
| 已知文件路径，只读单文件 | 命中 SKIP，直接 Read，不做 MCP 探测 |

本评测集用于规则与调用序列回归，不构成性能实测。评估 Token 收益时，对相同仓库状态和任务分别记录变更前后的工具调用次数、返回上下文 Token 与耗时，并计入首次检查成本；不能仅凭调用次数承诺节省比例。
