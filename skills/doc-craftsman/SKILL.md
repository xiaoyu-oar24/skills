# 结构化文档内容契约与接口文档原子化 (doc-craftsman)

> **核心思想**：文档检索应是"定点读取"而非"全量读取"。通过**原子化（One Topic / One API, One File）**与**Hub-and-Spoke 三级索引**，将数千行的巨石文档拆解为"索引定位 + 原子文件"结构——查找任意接口只需读 1~2 个索引页 + 1 个原子文件（约 200 行），相比全量读取可节省 90%+ 的 Token。
>
> **职责边界（三技能互补，本技能只做内容层与 specs 子结构）**：
> - `docs-layout-quadrant` = **五维骨架**：目录结构、档位判定、生命周期归档、`aidocs/INDEX.md` 全局索引、Agent-Friendly frontmatter → 本技能**遵循不重复**。
> - `doc-craftsman` = **内容契约 + `specs/接口文档/` 子体系**：文档内容怎么写、巨石文档怎么拆、接口子体系怎么导航。
> - `lean-docs` = **治理收敛**：内容冗余精炼、SSOT 聚合、检索阻断 → 内容冗余让位，结构混杂归本技能。

## 🎯 触发条件

- **TRIGGER when**:
  - 用户显式输入 `/doc-craftsman`
  - 用户要求"创建文档"、"编写接口文档"、"拆解大文档"、"更新接口文档索引"
  - 用户要求"扫描/盘点文档目录"、"找出过长或混杂的文档"、"批量诊断文档结构"且未指定具体文件 → 进入阶段 0 的目录级扫描模式（输出诊断清单，经用户确认后批量拆解；目录归类与五维合规检查仍让位 `docs-layout-quadrant`）
  - 需新建或更新以下类型的结构化文档：
    1. **接口契约文档**（RESTful API / RPC / TypeScript 类型定义）
    2. **技术规范与架构决策**（Specs / ADR / 数据模型）
    3. **业务需求描述**（PRDs / 业务规则 / 交互流程）
    4. **开发与操作指南**（Guide / How-to 操作手册）
  - 现有文档为**巨石堆砌**（>300 行且含 ≥2 个独立接口/主题）、索引断链或缺少结构化模板需重构
- **SKIP**（与相邻技能的显式豁免裁定）:
  - 进行中的端到端功能开发任务 → 按项目常规流程处理，不自动激活 `xy-feat`；若用户已显式调用 `/xy-feat`，则由该工作流调度，其阶段 6 按需调用本技能做接口契约拆分时不受此 SKIP 限制。
  - **五维归类、档位判定、生命周期归档、`aidocs/INDEX.md` 全局索引、frontmatter 状态机** → `docs-layout-quadrant`（本技能不重复实现）
  - **文档瘦身（内容冗余精炼）、特性群 SSOT 聚合、检索噪音阻断** → `lean-docs`（本技能只处理"结构混杂"拆解，不处理"内容冗余"精简）

## ⚙️ 依赖与先决条件

- **目录体系**：优先采用 `docs-layout-quadrant` 定义的 `aidocs/` 五维结构；接口契约存放于 **`aidocs/specs/接口文档/{domain}/`**。若项目使用传统 `docs/`，遵循其对应层级路径。
- **版本对齐**：依赖 `docs-layout-quadrant ≥ v3.3.0`（其阶段 2.5 放行 `specs/接口文档/` 子体系：英文 kebab-case 命名豁免、元信息表头 frontmatter 豁免、INDEX 域级入口覆盖放行）。`docs-layout-quadrant` 升级主版本时，需同步复核本技能对子体系放行规则的引用。
- **降级声明**：`docs-layout-quadrant` 不可用时，frontmatter 按最小头 `status / tier / domain / updated_at` 内联执行；`lean-docs` 不可用时，结构混杂拆解仍由本技能执行（内容冗余精炼在无 lean-docs 时跳过并说明）。
- **文件工具链**：支持 `Read`、`Write`、`Edit` 及文件搜索工具（限定目录范围，绕开构建产物/依赖目录）。
- **版本控制**：Git 工作区正常，修改前后保持版本可追踪。

## 📖 标准工作流

```text
[阶段 0: 目标解析与扫描] → [阶段 1: 类型识别与定位] → [阶段 2: 原子化编写/拆解] → [阶段 3: 三级索引联动] → [阶段 4: 链接自愈与合规验证]
```

> **两阶段执行协议（涉及拆解/批量创建时强制遵守）**：
> 1. **诊断阶段（只读）**：分析目标文档、产出拆解计划与影响范围清单，此阶段禁止任何写操作；
> 2. **用户确认**：将拆解计划提交用户，等待明确确认（回复"确认/执行/同意"等肯定语义）；
> 3. **执行阶段（落盘）**：用户确认后**必须实际执行**——创建原子文件、下沉共享约定、更新三级索引、自愈链接，禁止停留在建议或计划层面，禁止确认后再次输出计划重复请示。

### 阶段 0：目标解析、规模预判与拆解分流

**使用工具**：`Read`、文件搜索（Glob / Grep，限定 `aidocs/` 目录范围，排除 `.archive/`）

1. **目标解析**：判断入口模式——用户已指定目标文档为**定点模式**（进入第 3 条）；用户要求扫描/盘点目录但未指定文件为**扫描模式**（进入第 2 条）。
2. **目录级扫描（扫描模式专用）**：
   - Glob 枚举 `aidocs/**/*.md`（排除 `.archive/` 与各级 `INDEX.md`），对 >300 行的候选文件逐个读取，判定是否含 ≥2 个独立接口/主题；
   - 产出**诊断清单**（只读，禁止任何写操作）：① 巨石混杂文档 → 本技能按两阶段执行协议拆解；② 冗余流水账/废弃过程记录 → 标注移交 `lean-docs`；③ 归类/命名/生命周期问题 → 标注移交 `docs-layout-quadrant`；
   - 诊断清单附每个巨石文档的拆解计划（目标原子文件列表、共享约定下沉项、索引联动范围），一并提交用户确认。
3. **规模预判（定点模式）**：读取目标文档，按以下阈值分流：
   - 单文件 ≤300 行或单一主题 → 进入阶段 2 的"规范化编写/原地更新"分支；
   - 单文件 >300 行且含 ≥2 个独立接口/主题 → 进入阶段 2 的"存量拆解"分支。
4. **分流裁决**（与相邻技能的硬性边界，命中即让位）：
   - 文档内容是**冗余流水账/废弃方案/历史过程记录**（非多主题混杂）→ 让位 `lean-docs` 精炼；
   - 仅需**五维归类、命名校验、生命周期归档** → 让位 `docs-layout-quadrant`；
   - **多主题/多接口混杂且内容有效** → 本技能执行拆解。

### 阶段 1：类型识别与目标定位

**使用工具**：`Read`

1. **识别文档类别与目标象限**：
   - **接口契约 (API Specs)**：`aidocs/specs/接口文档/{domain}/`（唯一约定，不再二选一）。
   - **技术架构 (Specs/ADR)**：`aidocs/specs/`。
   - **业务需求 (PRD/Reqs)**：`aidocs/reqs/`。
   - **操作指南 (Guide/How-to)**：`aidocs/guide/`。
2. **确定原子化命名规范**（遵循 `docs-layout-quadrant` 命名原则的豁免项）：
   - 接口文档：`{module}-{sub}-{action}.md`（如 `basic-supplier-create.md`、`system-dept-page.md`），接口场景允许英文 kebab-case 以保证精确性。
   - 主题/规范文档：`{domain}-{topic}.md` 或简明中文领域名（如 `网关代理转发.md`）。
   - **严禁时间戳前缀**（如 `2026-09-01-xxx.md`）。

### 阶段 2：原子化编写与拆解

**使用工具**：`Read`、`Write`、`Edit`

1. **新建文档规范**：
   - **文档头**：接口契约文档使用「元信息表」（属性/值，含接口路径、方法、认证、权限标识、源码位置、前端封装、状态），以**项目规则文件为准**（如 `back/CLAUDE.md`「接口文档规范」章节）；无项目规范时遵循 `docs-layout-quadrant` 的 Agent-Friendly 最小头（`status / tier / domain / updated_at`）。
   - **接口契约七节结构**（对齐真实项目最佳实践）：
     1. 标题 + 概述（一句话职责）
     2. 元信息表（路径/方法/认证/权限/源码位置/前端封装/状态）
     3. 请求参数（字段表：字段名、类型、必填、校验规则、说明/枚举展开）
     4. 请求示例（HTTP / JSON 完整可运行）
     5. 响应参数与示例（含成功/失败结构）
     6. 错误码表（错误码数值、错误信息模板、触发条件）
     7. 前端调用示例（TypeScript 封装 + 注意事项）
   - 单文件聚焦单一主题，建议 50 ~ 250 行。
2. **存量文档拆解（巨石文档）**：
   - 按接口/功能拆分为多个独立原子文件（每个接口一个文件）。
   - **共享约定下沉**：URL 前缀、数据模型、错误码体系、并发控制等跨接口共享约定，**只写一份**到模块子索引的「架构与业务约定」节，原子文件不复述（这是降 Token 的核心设计）。
   - 原巨石文件保留架构决策与接口总览，接口细节链接指向原子文件（或整体重构为模块子索引）。

### 阶段 3：三级索引联动

**使用工具**：`Read`、`Edit`、`Write`

每当新增、重命名或拆解文档后，必须强制同步以下三级索引：

1. **模块子索引 (Sub-Hub: `{domain}/INDEX.md`)**：
   - 聚合当前业务域内全部原子文档，含「接口清单」表（接口名称、HTTP 方法 & 路径、简述、文档链接）+「架构与业务约定」节（共享约定唯一存放点）。
2. **域总索引 (Domain Hub: `specs/接口文档/INDEX.md`)**：
   - 按模块分组；模块文档多时只保留一行跳转链接（如 `[supplier/INDEX.md](supplier/INDEX.md)`），避免重复展开。
3. **全局索引入口 (Global Hub: `aidocs/INDEX.md`)**：
   - 仅维护「接口文档」域的**入口一行**（格式遵循 `docs-layout-quadrant` 阶段 4 模板）；由本技能在新增域时更新，但格式与完整性校验归 `docs-layout-quadrant`。

### 阶段 4：链接自愈与合规验证

**使用工具**：`Read`、文件搜索

1. **相对路径校验**：本技能子体系内所有 Markdown 链接必须为相对路径且目标文件真实存在。
2. **消除空壳**：严禁创建仅有标题无实质内容的空占位文件。
3. **委托校验**：frontmatter 生命周期状态、`aidocs/INDEX.md` 完整性 → 交 `docs-layout-quadrant` 执行（本技能不重复实现）。

## ⛔ 行为护栏

1. **禁止事实编造**：字段类型、枚举值、错误码、业务规则必须基于真实代码、DTO 或既定规范，不确定项明确标注 `待确认`。
2. **单主题原子化红线**：严禁将多个不相关的业务功能或多个 REST 接口混合写在同一个超大文档中。
3. **禁止绝对路径链接**：文档间交叉引用必须使用标准相对路径。
4. **禁止孤岛文档（子体系索引必须闭环）**：新增/移动/拆解文档后必须同步更新模块子索引与域总索引，严禁产生未被索引引用的孤岛文件；新增域时必须同步 `aidocs/INDEX.md` 入口一行。
5. **破坏性变更确认 + 确认后必须落盘执行**：重命名已存在文档、删除废弃文件或拆解存量文档前，必须说明影响范围并获得用户确认；一经确认，必须完成全部拆解与三级索引联动落盘，禁止停留在建议层面。
6. **禁止整目录盲目覆写**：更新索引或微调文档时使用 `Edit` 精确修改，严禁不经读取盲目 `Write` 覆盖已有文件。
7. **不越界相邻技能职责**：不定义 `aidocs/INDEX.md` 格式、不定义 frontmatter 生命周期状态机、不重复实现归档（让位 `docs-layout-quadrant`）；不做内容冗余精炼与 SSOT 聚合（让位 `lean-docs`）。内容冗余与结构混杂并存时，先让 `lean-docs` 精炼，剩余结构混杂再拆解。

## 📝 模板与范例

### 模板 1：原子化接口契约文档（七节结构，`{domain}/basic-supplier-create.md`）

````markdown
# POST /admin-api/basic/supplier/create — 暂存供应商准入

> 录入供应商基本信息并初始化组织准入草稿，状态置为「5-暂存」。

## 一、元信息
| 属性 | 值 |
| :--- | :--- |
| 接口路径 | `/admin-api/basic/supplier/create` |
| 请求方法 | `POST` |
| 认证方式 | Bearer Token（Header `Authorization`） |
| 权限注解 | `@ss.hasPermission('basic:supplier:create')` |
| 前端 API 封装 | `api/basic/supplier.ts` |
| 状态 | 已实现 |

## 二、请求参数
| 字段名 | 类型 | 必填 | 校验规则 | 业务说明 |
| :--- | :--- | :---: | :--- | :--- |
| `supplierName` | string | 是 | `@NotBlank` | 供应商名称（全局唯一） |
| `supplierType` | number | 是 | - | 类型：`1`-生产商, `2`-贸易商, `3`-服务商 |

## 三、请求示例
```http
POST /admin-api/basic/supplier/create HTTP/1.1
Content-Type: application/json
{ "supplierName": "华北再生资源有限公司", "supplierType": 1 }
```

## 四、响应参数与示例
| 字段名 | 类型 | 说明 |
| :--- | :--- | :--- |
| `code` | number | 业务状态码（`0` 成功） |
| `data` | string | 新生成的供应商编码 |

## 五、错误码表
| 错误码 | 错误信息模板 | 触发条件 |
| :--- | :--- | :--- |
| `1002402102` | 供应商统一社会信用代码或名称重复 | 已存在同名或同信用代码记录 |

## 六、前端调用示例
```typescript
export const createSupplier = (data: SupplierSaveReqVO) =>
  request.post<string>({ url: '/basic/supplier/create', data })
```

## 七、注意事项
1. 调用成功后主数据与组织关系表版本号初始化为 `1`，准入状态置为 `5`（暂存）。
````

### <Bad> vs <Good> 交互与操作范例

#### <Bad> — 巨石堆叠 + 共享约定重复 + 死链
```markdown
# 错误做法：
1. 在 `docs/api.md` 单一文件追加 50 个接口，文件长达 3000 行——每次检索都全量读取。
2. 每个接口文档都重复粘贴"URL 前缀 /admin-api、错误码体系"——约定改一处漏十处。
3. 内部链接使用绝对路径 `[详情](/Users/dev/project/docs/api.md#section2)`。
4. 未在任何 INDEX 登记，新增接口成为信息孤岛。
```

#### <Good> — 原子解耦 + 共享约定下沉 + 三级索引联动
```markdown
# 正确做法：
1. 在 `aidocs/specs/接口文档/supplier/` 下创建独立原子文件 `basic-supplier-create.md`（仅该接口七节契约）。
2. 在 `supplier/INDEX.md` 的「接口清单」表登记 `[basic-supplier-create.md](basic-supplier-create.md)`，并将跨接口共享约定写入「架构与业务约定」节（只写一份）。
3. 在 `specs/接口文档/INDEX.md` 域总索引登记 supplier 模块（文档多时仅留一行跳转）。
4. 在 `aidocs/INDEX.md` 维护「接口文档」域入口一行（格式遵循 docs-layout-quadrant）。
5. 全部链接使用相对路径；检索任一接口只需读 2 个索引 + 1 个原子文件。
```

## 📜 版本变更历史

- **v1.1.0** (2026-09-02):
  - **目录级扫描模式**：阶段 0 新增目标解析与扫描分支——用户未指定文件时 Glob 枚举 `aidocs/**/*.md`（排除 `.archive/` 与 `INDEX.md`），产出三分诊诊断清单（巨石混杂本技能拆解 / 冗余流水账移交 lean-docs / 归类归档移交 docs-layout-quadrant），解决"只能定点、不能扫描"的入口缺口。
  - **两阶段执行协议**：新增"诊断（只读）→ 用户确认 → 强制落盘执行"协议，确认后禁止停留在建议层面，解决"只给建议不动手"的执行缺口；护栏第 5 条同步强化。
  - **触发词补全**：description 与 TRIGGER 补充"扫描/盘点文档目录"、"批量诊断文档结构"触发词，并显式标注目录归类仍让位 `docs-layout-quadrant`。
- **v1.0.0** (2026-09-02):
  - **职责收敛**：定位收敛为"结构化文档内容契约 + `specs/接口文档/` 子体系原子化"，明确三技能互补边界——frontmatter 生命周期、`aidocs/INDEX.md` 格式、生命周期归档让位 `docs-layout-quadrant`；内容冗余精炼、SSOT 聚合让位 `lean-docs`。
  - **三级索引落地**：固化"域总索引 → 模块子索引 → 原子文件"三级结构（取代含糊的"两级/三级"表述），并新增**共享约定下沉**规则——跨接口约定只写一份到模块子索引「架构与业务约定」节。
  - **模板升级**：接口契约模板对齐真实项目七节结构（元信息表 / 请求参数含校验规则 / 请求示例 / 响应与示例 / 错误码表 / 前端调用示例 / 注意事项）；新增域总索引模板与模块子索引模板（含约定下沉节）。
  - **接口路径定案**：唯一约定 `aidocs/specs/接口文档/{domain}/`（删除 `specs/api/` 二选一）。
  - **阶段 0 分流闸**：新增规模预判与分流——>300 行且 ≥2 独立接口/主题才拆解；内容冗余让位 lean-docs，归类归档让位 docs-layout-quadrant。
  - **护栏**：新增第 7 条"不越界相邻技能职责"，护栏总数 7 条。
