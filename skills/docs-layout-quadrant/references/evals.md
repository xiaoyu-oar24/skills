# docs-layout-quadrant 触发评测集

> 评估驱动开发：修改 `description` 或触发条件后，用以下提示词回归验证路由行为。

## 应触发（Expected：激活）

1. "aidocs/ 目录太乱了，帮我整理成规范结构"
2. "这个新功能的设计文档应该放在哪个目录？"
3. "发现好多文档带 `2026-07-` 日期前缀，帮我统一处理"
4. "把 aidocs 目录结构说明注入到 AGENTS.md / CLAUDE.md"
5. "AGENTS.md 里的 docs-layout-quadrant 标记块好像过期了，帮我更新"
6. "我写了一份需求文档「一口价订单成交通知单查看与下载.md」，应该放哪里？"
7. "这是一个纯性能优化任务，需要单独写需求文档吗？"
8. "这个功能只有 2 个步骤，还需要单独的 tracking.md 吗？"
9. "项目里的 docs/ 是五维结构的旧版布局，帮我迁移到 aidocs/"（阶段 0 自动迁移）
10. "docs/ 里既有 VitePress 文档站又有 specs/plan 目录，帮我隔离一下"（混合占用迁移）

## 档位判定（Doc-Tier Gate）专项评测

### 应判定 L0 轻量（零文档）
1. "修复登录接口超时 500 的 bug，只改一个文件"
2. "把按钮颜色从蓝色改成灰色，纯样式微调"
3. "修改一下 .env 里的超时时间配置"
4. "这次任务只有 2 步：改个文案 + 发个 PR，不用写文档"

### 应判定 L1 精简（核心资产）
1. "给分页组件加一个自动加载更多功能，单模块、单线程"
2. "重构一下用户模块的登录逻辑，有新的接口契约要沉淀"
3. "这个新组件做完了，要不要写个 specs？plan 和 tracking 就别落盘了"

### 应判定 L2 全量（五维全出）
1. "拆分子订单服务，涉及订单/支付/库存三个模块"
2. "这个功能要派多个子代理并行开发，需要完整文档流程"
3. "用户明确要求：这次走完整五维文档流程"

## 不应触发（Expected：跳过）

1. "帮我改一下项目根目录的 README.md"
2. "更新 CLAUDE.md 里的项目介绍段落"（编辑标记块之外的普通内容，非结构注入）
3. "帮我写一篇代码注释规范"（内容创作，非目录整理）
4. "帮我调整 docs/ 下 VitePress 文档站的导航配置"（docs/ 非五维内容，不属于本技能边界）

## Agent-Friendly 专项评测（v3.2）

1. "帮我给 aidocs 新文档加一个机器可读状态头" → 应要求 `status/tier/domain/updated_at`，必要时加 `source_workflow`
2. "设计文档已批准，接下来怎么标记？" → 应更新 `status: approved`，交付后使用 `delivered`
3. "文档已经移入 .archive/specs 了，还要改什么？" → 应同步 `status: archived`
4. "INDEX 里有个链接打不开" → 应执行相对链接完整性校验并修复
5. "L1 的任务进度只在聊天记录里，新会话怎么继续？" → 应读取或补写 specs 的 `Execution State`

## 接口文档子体系专项评测（v3.3）

### 应触发（Expected：激活）

1. "新增了 `specs/接口文档/supplier/` 子目录和 6 个原子接口文件，全局 INDEX 校验不通过，怎么处理？" → 应放行：原子接口文件不逐条进全局 INDEX，以「接口文档」域级入口一行计。
2. "接口契约文件用 `basic-supplier-create.md` 英文命名，符合命名规范吗？" → 应豁免"优先中文命名"，接口场景允许英文 kebab-case。
3. "接口文档没有 YAML frontmatter 只有元信息表，合规吗？" → 应以项目接口文档规范为准（允许元信息表头）；无项目规范时建议补充最小头。
4. "`specs/接口文档/` 下的接口文档要归档吗？" → 不应自动归档：接口文档属 specs 核心资产，生命周期不随 plan/tracking 归档。

### 不应触发（Expected：跳过）

1. "帮我编写一个创建供应商的接口契约文档" → 应跳过，转 `doc-craftsman`（子体系内容维护归它，本技能只做放行与校验）。
