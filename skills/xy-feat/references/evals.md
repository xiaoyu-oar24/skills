# xy-feat 触发评测集

> 评估驱动开发：修改 `description` 或触发条件后，用以下提示词回归验证路由行为。本技能刻意收窄为仅显式调用，"不应触发"用例与"应触发"同等重要。

## 应触发（Expected：激活）

1. `/xy-feat 做一个文件上传功能`
2. `/xy-feat`（空需求，预期先追问"你要做什么功能？"）
3. `/xy-feat 给网关加代理转发，用隔离 worktree 开发`

## 不应触发（Expected：跳过）

1. "开发一个新功能"（自然语言描述，未显式输入 `/xy-feat`）
2. "帮我写一个用户登录特性"
3. "这个 xy-feat 技能的文件在哪个目录？"（询问技能本身，不是调用工作流）

## 档位判定专项评测（阶段 0 Doc-Tier Gate）

> 以下用例验证阶段 0 档位判定的正确性——触发后应产出对应档位的文档，而非一律五维全出。

### 应判定 L0 轻量（零文档，不建任何 aidocs/ 文件）
1. `/xy-feat 修复登录接口超时 500，只改一个文件`
2. `/xy-feat 把按钮颜色改成灰色，纯样式微调`

### 应判定 L1 精简（specs + guide 按需，plan/tracking 不落盘）
1. `/xy-feat 给分页组件加自动加载更多，单模块单线程`

### 应判定 L2 全量（五维全出）
1. `/xy-feat 拆分子订单服务，涉及订单/支付/库存三模块`
2. `/xy-feat 这个功能要用多子代理并行开发，走完整文档流程`
